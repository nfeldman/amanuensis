Codebase

Use it when you are looking for the part of the code that does something.

Terms on this page

Subsystem
A part of the codebase the survey treats as one unit, with its own files and its own page. The agent chose the split during onboarding.
Layer
A group of subsystems with a similar role. Pages group subsystems by layer.
Survey depth
How far the survey of a subsystem has got. Unmapped: not started. Scoped and Structural: that pass is done. Reviewing concerns and Challenging claims: that pass is under way. Mapped: every pass is done. Deferred: left out of the survey on purpose. Each depth limits what the record may claim.
Mapped
The last survey depth: every pass has run. It does not mean every file is read or every bug found.
Scope
The files a subsystem owns, each marked as read, not yet read, or left out with a reason.
Finding
A defect the survey confirmed, with evidence, a severity, and a state (open, repaired, verified, ruled out, accepted).

Purpose

This is how agents ask the survey what it knows. describe_locus answers for one file, symbol, subsystem or term, and leads with its standing, so an unread or stale file is not mistaken for a read one. get_attention lists what is unresolved, get_history what was concluded, and get_dashboard gives project totals. Store schema, migrations and storage history

ID
P-02
Status
Mapped
Findings
1 (1 open)
Priority
1

Purpose

The store is memory.db, a SQLite file. This part defines its schema; triggers bar deletes from 104 tables and freeze listed columns. Opening migrates old stores and refuses one lacking a declared table, view, index or trigger. Tools call its checks to refuse what a subsystem's status or the store's reconciliation does not allow. Phase gates and session ends commit the store to git if in a repo.

Scope

memory.db: the SQL schema with its views and append-only triggers, opening and migrating a store (db.ts), the server-side invariants that turn the epistemic contract into refusals (invariants.ts), the storage directory's own git history (storage-git.ts, commit_phase_gate, get_storage_history), and their tests.

Start here

mcp-server/src/db.ts, then mcp-server/src/schema.sql and mcp-server/src/invariants.ts

Purpose

The code index lets a survey session read a codebase by its definitions at any commit: outline_file lists a file's definitions, read_symbol returns one by name with its source, and find_symbol searches a whole revision. add_evidence uses it to anchor a cited symbol to an exact, hashed span. Purpose

It renders memory.db, opened read-only, as a static HTML site in the store's docs directory. The server's materialize_docs tool runs it. A render refuses when the latest exclusions fail their digest. Status
Mapped

Purpose

Evidence cites a file's lines at a resolved commit; a given symbol is tied to its definition if the code index reads the file. A claim is a typed statement over evidence, valid from one revision until closed there or at a descendant. A finding's resolution history is deleted with the finding on a subsystem reset. Overturning a finding or verifying its fix needs evidence from the session doing it.
