Terms on this page

Evidence
A pointer to code at a commit (file, symbol, lines) with a note of how strong it is: read in code, seen in a test, stated in a comment, and so on.
Challenge
A pass in which the agent tries to prove its own claims and findings wrong. Each claim records whether it survived.
Finding
A defect the survey confirmed, with evidence, a severity, and a state (open, repaired, verified, ruled out, accepted).

Pushing a v* tag publishes the npm package without the tests workflow having run on that commit, and every version, beta prereleases included, is published under the latest dist-tag.

ec393801

After accepted r1, a rejected successor r2, and a reconsideration r3 drafted on r2 and accepted, both r1 and r3 have status accepted; get_decision shows two accepted revisions, detect_decision_impacts opens blocking obligations and impact events against r1 as well, and r1 can still be invalidated as if it held authority.

Why it matters

Decision custody exists to say which revision carries authority. Status
Open
Revision
ec393801

When a materialize_docs render outlives its 900 s bound while page models are being built, the SIGTERM the server sends does not stop it: the render runs to completion with one page missing and a warning, the server stays blocked in spawnSync until it exits, and the tool then reports "materializer failed to start" with the timeout error and records no read-back.

Why it matters

The bound exists so one render cannot hang the server for good (comment at the spawn). M04-1

Status
Open
Revision
ec393801

An imported artifact body can contain a line that begins '<!--' and ends '-->' with markup between, for example '<!-- a --><script>…</script><!-- b -->'.

Observed behavior

Such a line is published as live HTML on the page that renders that body.

Why it matters

Record text is meant never to reach a page as markup. Imported bodies are earlier hand-written artifacts read from the storage directory, so exploiting this needs write access there. Root cause

legacy_prose.parse accepts any such line as a RecordMarker without the _MARKER_RE check that prose.py applies to inline markers. html_projection's writer prints RecordMarker.raw (and the joined record and row markers) verbatim, trusting the producer for markers although it escapes every other node.

Status

Observed behavior

Root cause
