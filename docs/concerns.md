## Active concerns

| Code | Category | Origin | Discovered in | Notes |
|---|---|---|---|---|
| <a id="al-1"></a>**AL-1** | aliasing-and-ownership-violation | seeded | — | A module-level mutable object — a tool-definition array, a parsed contract, a vocabulary table, a cached project record — is handed to a caller or a handler that can mutate the server's own copy, so one tool call changes another's behaviour for the life of the process. TypeScript object spread is shallow, so a defensive copy of a nested contract is not one. |
| <a id="at-1"></a>**AT-1** | atomicity-violation | seeded | — | A handler writing more than one table is not wrapped in a single SQLite transaction, so an invariant check or a constraint failure part-way leaves the store internally inconsistent — a finding with no opening resolution event, a disposition with no evidence link, a dispatch with no landing. |
| <a id="at-2"></a>**AT-2** | atomicity-violation | seeded | — | The storage Git commit and the database mutation it is meant to make recoverable can diverge: the commit runs but omits the mutation (WAL not checkpointed), or the mutation lands with no commit. The storage repository's history is the only record of a store that Git does not track, so a commit that does not contain the mutation is silent data loss on the next discard. |
| <a id="cc-1"></a>**CC-1** | cache-coherence-failure | seeded | — | A generated artifact — docs/, DEVELOPMENT.md's tool inventory, src/vocabulary.ts and vocabulary.py, ROADMAP.md, any dev/ receipt — is not regenerated when its source changes, and no check detects the drift. This repository generates a great deal and asserts drift checks on some of it; the concern is the generated output that has no --check. |
| <a id="cc-2"></a>**CC-2** | cache-coherence-failure | seeded | — | A derived SQL view (file_standing, finding_state_current, finding_summary, concern_coverage, hot_subsystems) or a derived counter on the dashboard disagrees with the tables it is computed from, so two readers of one store answer differently. Falsifiable statically by reading each view definition against its writers. |
| <a id="cr-1"></a>**CR-1** | concurrency-race-windows | seeded | — | Two server processes bound to one store — the documented case, since one Codex or Claude installation serves every repository and linked worktrees share a storage root — race on a write the active_write_locks table does not cover, or on a lock whose acquisition is not itself atomic. |
| <a id="cr-2"></a>**CR-2** | concurrency-race-windows | seeded | — | First use creates the store lazily. Two first uses can race and create it twice, or an interruption between creating the directory, applying the schema, and publishing the completion marker can leave an incomplete store that a later open accepts as complete. The laziness is a deliberate activation property, which makes its interruption boundaries a contract surface rather than an edge case. |
| <a id="ep-1"></a>**EP-1** | exceptional-path-invariant-asymmetry | seeded | — | A failure part-way through a multi-file write leaves a partially written store, docs tree, or host configuration file, and no path restores the pre-operation state. This system deliberately writes outside SQLite (the storage directory, the promoted docs/, Codex and Claude config) where a transaction cannot help it, so each such site needs its own rollback and each rollback needs to be reachable. |
| <a id="ep-2"></a>**EP-2** | exceptional-path-invariant-asymmetry | seeded | — | An error path skips something the success path performs — releasing a write lock, closing a session, committing the storage snapshot, recording a dispatch landing. The methodology treats an uncommitted checkpoint as lost work, so a throw that bypasses commit_phase_gate is a data-durability defect and not merely untidy. |
| <a id="id-1"></a>**ID-1** | scope-context-identity-conflation | seeded | — | A record keyed by a caller-supplied identifier (finding_id, claim_key, subsystem id, concern code, artifact path) is reused across a store generation, a repository binding, or a worktree without the key carrying the thing that distinguishes them — so a reference minted against one generation silently resolves against another. Falsifiable statically: read every id-minting and id-resolving site and ask what the key does NOT include. |
| <a id="id-2"></a>**ID-2** | scope-context-identity-conflation | seeded | — | An evidence, claim, or ledger row identifies a locus as file_path plus symbol but is read back without the revision it was recorded at, so a row that was true at ref_sha is served as current. The store is explicitly revision-binding, which makes any read path that drops ref_sha a contract violation rather than an oversight. |
| <a id="if-1"></a>**IF-1** | incremental-full-path-divergence | seeded | — | The diff-aware incremental publish and clean_publish do not produce the same tree from the same store state — a page, an anchor, a manifest entry, or a contract hash present under one and not the other. The materializer is explicitly diff-aware, so both paths exist by design and only one of them is exercised by most runs. |
| <a id="if-2"></a>**IF-2** | incremental-full-path-divergence | seeded | — | The incremental drift detector (detect_changes, ledger-derived staleness) and a full reconciliation disagree about which scoped files are stale, so the backlog a refresh works is not the backlog that exists. This project has already recorded a whole inert staleness surface, which is the extreme case of this divergence. |
| <a id="rl-1"></a>**RL-1** | resource-lifecycle-asymmetry | seeded | — | A SQLite handle, a spawned child process, or a temporary directory is acquired without a guaranteed release on every exit path. The server's own rebuild procedure exists because a handle lives for the life of the process, so handle lifetime is a known-load-bearing property here rather than a generic hygiene item. |

| <a id="se-1"></a>**SE-1** | seam-contract-violations | seeded | — | A contract stated on one side of a seam is not enforced on the other: the skill's prose promises a step the tools do not require, a JSON Schema declares a shape no validator checks, or a receipt asserts a property its checker never reads. The repository's own stated policy — load-bearing contracts belong in the server, not in agent prose — makes every prose-only contract an instance of this concern until shown otherwise. |
| <a id="tb-1"></a>**TB-1** | temporal-bound-violation | seeded | — | An exogenous subprocess — git, python3, lsof, ps, node, the pecia CLI — is invoked from a server startup path or a tool handler without a timeout, so a hung child hangs the MCP host's request. Node's execFileSync/spawnSync default to no timeout, which makes this the default rather than an oversight. Probe: every execFileSync/spawnSync/spawn call site in mcp-server/src and every subprocess call in the materializer. |
| <a id="tr-1"></a>**TR-1** | trust-boundary-elision | seeded | — | Every tool argument is model-authored. One reaches a filesystem path, a subprocess argument, or a SQL identifier without validation, so a generated value escapes the bound workspace or the parameter list. The binding contract is an application containment guarantee and not an OS sandbox, which puts the whole weight of containment on these checks. |
| <a id="tr-2"></a>**TR-2** | trust-boundary-elision | seeded | — | Content stored by one writer and read back into another agent's context or into generated HTML is treated as instruction or as safe markup rather than as untrusted data. Store rows are model-authored prose; the published projection is HTML a person opens in a browser. The pecia resolver already refuses to echo its argument for exactly this reason, which establishes the class as live in this codebase. |
| <a id="vr-1"></a>**VR-1** | scope-context-identity-conflation | seeded | — | A version, revision, or digest is stated in more than one place with no single source and no check binding them, so the places drift. Instances to test: the package version against the server's SERVER_VERSION and the documentation; a receipt's digest against the file it binds; the skill version in a packaged copy against the source checkout. |
| <a id="zd-1"></a>**ZD-1** | validation-zero-denominator | seeded | — | A gate reports green while asserting over an empty set — the store it reads is absent, the query returns no rows, the fixture list is empty, or the missing-file exit is accepted as a red. This repository has recorded the failure three times already (its own history names B03-2, B04-1 and B04-3), which makes it the local recurrence rather than a generic worry. Falsifiable statically: for each assertion, find the denominator and ask what makes it non-zero. |
