Terms on this page

Survey
The agent's reading of the repository, done in passes, with each conclusion tied to the code it read.
Subsystem
A part of the codebase the survey treats as one unit, with its own files and its own page. The agent chose the split during onboarding.
Survey depth
How far the survey of a subsystem has got. Unmapped: not started. Scoped and Structural: that pass is done. Reviewing concerns and Challenging claims: that pass is under way. Mapped: every pass is done. Deferred: left out of the survey on purpose. Each depth limits what the record may claim.
Mapped
The last survey depth: every pass has run. It does not mean every file is read or every bug found.
Scope
The files a subsystem owns, each marked as read, not yet read, or left out with a reason.
Concern
One kind of defect worth looking for in this codebase, such as a race on a shared cache. The review checklist is the full list.

§Paths with no ledger row

§Files in scope that no one has read

0 of 2 ledger rows that carry a survey obligation are classified candidate: the file participates in its subsystem and no one has read it.

§Subsystems set aside

0 of 3 subsystems are deferred. Deferred is not a rung on the survey ladder but an orthogonal do-not-survey flag, so nothing in them has been surveyed at any depth.

§Seam sides no one has assessed

No (seam, side) pairs is recorded, so this gap is not measured here. That is a statement about the record, not a claim that the gap is closed.

Binding: per-party-proxy; no seam-bound disposition is recorded. An SC-% disposition says a party has assessed some seam concern, never that it assessed this seam.

§Concerns no one has dispositioned here

3 of 3 (subsystem, active concern) pairs carry no disposition. The unit is the pair: a concern dispositioned somewhere else says nothing about this subsystem, and counting concern codes would report a checklist as complete while most regions were never tested against it.
