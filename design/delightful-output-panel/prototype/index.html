Act on consequence, with the warrant attached

The lead rule is inspectable: severity, reachable surface, evidence strength, and the next decision. “Critical” does not erase the deployment boundary that still needs confirmation.

CriticalOpenCode verifiedV02-1 · V-02

Unauthenticated HTTP requests can read and write as the system tenant

The HTTP SPARQL surface consults no authorization policy. With no tenant header, it selects the system context, applies no tenant row filter, and exposes query, update, and admin routes. The standalone bootstrap starts this surface and defaults its bind address to 0.0.0.0:7474.

Do first · containment before prescription

  • Confirm whether the standalone HTTP surface is deployed or exposed.
  • If exposed, restrict or disable it while policy wiring and tenant derivation are reviewed.
  • Then decide the repair boundary: transport auth layer, handler checks, or both.

Visible qualification

Open question #4 asks whether the standalone server is a supported shipping target. That changes practical reach and grade calibration; it does not change the observed absence of HTTP authorization in this repository.

Open the evidence aperture · three composing decisions
  1. No transport authorization: the HTTP router and handlers contain no AuthzPolicy consultation while gRPC handlers call policy inline.
  2. Privileged default: resolve_http_tenant_context derives identity from an unauthenticated header and substitutes _system when absent.
  3. No row filter: the system context becomes tenant_id = None, so the query pipeline applies no tenant predicate. Bootstrap makes the surface reachable by default.

Receipts: routes/mod.rs:65–85, http.rs:66–120, routes/sparql.rs:146–149, pipeline.rs:1504–1507, main.rs:360, config.rs:201. Ref SHA d19ade70.
