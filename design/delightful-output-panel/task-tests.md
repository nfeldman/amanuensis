# Reader-task tests

These are structured walkthroughs over representative AxiomDB content, not user-study results. “Pass” means the proposed information architecture visibly contains a short, coherent route; it does not establish real-reader performance.

## Frozen task fixtures

| Task | Starting condition | Observable completion |
|---|---|---|
| T1 · Orient | New engineer, five minutes, opens the report root | Can state what AxiomDB is, the write/reason/query/storage spine, what mapped authorizes, the most consequential current issue, and one sensible next page |
| T2 · Act | Maintainer asks “what requires action and why?” | Reaches `V02-1`; can state consequence, reachability, evidence basis, immediate containment/verification move, and source handles without reading a findings table laterally |
| T3 · Audit | Skeptical reviewer challenges trustworthiness | Separates checked SHA, mapped depth, finding severity, open questions, contradictions, and projection integrity; verifies current register agreement while seeing the earlier disagreement as a dated provenance event; reaches raw Markdown in one action |
| T4 · Re-enter | Returning reader has no recorded previous snapshot | Sees “no comparison recorded,” distinguishes active survey work from publication delta, and can resume at the named current trail without invented “since last visit” claims |
| T5 · Locate | Specialist looks for HTTP auth, `V-02`, or `x-axiomdb-tenant` | Finds the object from name/ID/topic, retains `Service / V-02` place, sees the critical case and related query/auth surfaces, and has an explicit return to the originating case |

## Concrete walkthroughs for the selected direction

### T1 · New engineer in five minutes

1. Reads the one-breath model: Rust-native RDF quad store; five embedded Fjall permutations; SPARQL through LTJ/Volcano; reasoning over the same storage boundary.
2. Reads the status band as four different claims, not one score: checked source, surveyed territory, open consequence, publication coherence.
3. Sees the lead critical issue but can choose “Understand the terrain” into the region atlas.
4. Reads “mapped” as a survey-depth authorization, not “correct.”

**Failure trigger:** The reader can repeat `25 / 34` but cannot say what the denominator or mapped status means.

### T2 · Maintainer responding to `V02-1`

1. Opens the lead case without visiting a table.
2. Closed case face states: unauthenticated HTTP query/update, system-tenant default, all-interface bind, `CRITICAL`, open, checked at `d19ade70`.
3. Visible “Do first” wording separates containment from repair: confirm whether the standalone server is exposed; disable/restrict HTTP while policy wiring and tenant derivation are reviewed.
4. Evidence aperture names the three composing decisions and links the full finding, `V-02`, `Q-01`, and open deployment-boundary question #4.

**Failure trigger:** Severity alone appears to prescribe a code fix before the shipping/exposure boundary is checked.

### T3 · Skeptical reviewer

1. Opens “Audit the record.”
2. Sees current capture agreement: overview and master plan both `25 / 34`; overview and findings register both `14 / 1 critical`. Projection integrity is a separate checked field, not implied by source freshness.
3. Can open the dated provenance note showing that an earlier capture disagreed (`22` vs `23` mapped; `13 / 0 critical` vs `14 / 1 critical`) without presenting that older state as current.
4. Sees that `0 unresolved contradictions` means no contradictory finding pairs recorded, not “the report is consistent” and not “the code is safe.”
5. Uses the Markdown-source link without JavaScript.

**Failure trigger:** A freshness mark is treated as more authoritative than a projection-integrity warning when one exists.

### T4 · Returning reader

1. Re-entry block says publication comparison is unavailable for this prototype baseline.
2. Reader-local state is explicitly labeled device-local and optional; it never rewrites the generated delta.
3. Active survey activity is a separate row, copied from the report's latest-session record.
4. “Resume” jumps to the named seam/current trail and shows current publication identity.

**Failure trigger:** A timestamp is paraphrased as “what changed” or an active session is presented as a completed publication delta.

### T5 · Specialist lookup

1. Types `V-02`, “HTTP auth,” or `x-axiomdb-tenant` into one semantic search field.
2. The match identifies object type, region, status, and open finding count.
3. Opening it preserves `AxiomDB / Service / V-02` plus an explicit `Return to V02-1 decision` route when case-led.
4. Relationship trail names `V-02 → V-03 authorization` and `V-02 → Q-01 query pipeline` as sentences, not unlabeled graph edges.

**Failure trigger:** The search only filters page titles or following a relationship destroys the original case context.

## Claims these tests do not authorize

- No timing, error rate, satisfaction, accessibility-conformance, or comprehension claim follows.
- The projection incoherence is an observed captured state, not yet diagnosed as an atomic-write bug.
- The selected direction is a panel judgment awaiting representative-reader and assistive-technology testing.
