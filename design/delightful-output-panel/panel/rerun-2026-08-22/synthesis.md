# Dialectical synthesis: Field Docket, tightened

## Evidence labels

- **[O] Observation:** directly visible in Amanuensis source or the current generated AxiomDB report.
- **[R] Research claim:** preserved with seven fields and source custody in the narrow Scholiast workspace.
- **[J] Judgment:** an orchestrator or panel design decision; it is not promoted to evidence.

Three independent memos agreeing is useful replication of a critique, not empirical validation of the redesign.

## Agreement without consensus theater

All three panelists independently found:

1. **[O]** The paper/ink editorial language, local assets, visible focus, and durable Markdown companionship are valuable and should survive.
2. **[O]** The overview is a snapshot inventory, not an action or re-entry surface.
3. **[O]** Findings contain decision-grade prose in comparison-table geometry.
4. **[O]** The 49-link rail is a complete index masquerading as persistent navigation.
5. **[O]** “Mapped,” “no stale entries,” finding state, and absence of contradictions answer different questions but can read like a single all-clear signal.
6. **[O]** The architecture page's raw diagram source fails its own “at a glance” promise.
7. **[O]** Mobile drawer semantics and accessible status explanations are incomplete.

## Conflicts deliberately preserved

| Conflict | Art direction | Wayfinding | Editorial | Orchestrator decision |
| --- | --- | --- | --- | --- |
| Governing object | Evidence fieldbook | Work queue / survey cockpit | Decision queue | **Decision docket inside a fieldbook frame**; no live-cockpit styling. |
| First eye | Three-sentence précis, then attention line | Resume/current work | Critical/high action and active-run caveat | **Identity + active-run caveat + consequence**, with the atlas one stable route away. |
| Architecture | Hyperlinked plate with restrained motion | First-class atlas route | Alternate overlay, not primary | **Coordinate, not homepage**; render only relationships the data actually supplies. |
| “Resume” | Named current trail | Initially personal history and suggested next action | Change/accountability lanes | **`Resume this report` from report-owned state only**; no “your last task,” inferred history, or unowned next action. |
| Editorial authority | Attention line | Ranked queue with “why next” | Consequence-led action queue | **Ordering rule is visible**; recommendations separate contain/verify from fix. |
| Density | Scan/Read modes | Task-specific local navigation | Progressive evidence disclosure | **One factual DOM, layered disclosure**; never hide a qualifier behind an optional view mode. |

The conflict is productive: a cockpit is clearest about action but falsely suggests telemetry and mutable workflow; an atlas is strongest for place but weak when all territory is mapped and critical findings remain open; an evidence edition is honest but can become an apparatus readers admire rather than use.

## Research boundary on re-entry

- **[R]** Logged programming sessions often include reconstructive navigation before editing (Scholiast C001; single-source, observational, historical).
- **[R]** Content-rich cues were preferred in one small interrupted-programming study, but measured lag differences were not statistically significant (C002; single-source with explicit null result).
- **[R]** Mylar-style task context depends on a named task and personal interaction history and has lifecycle/inference limitations (C003; single-source, historical field study).
- **[R→J]** A static report may expose snapshot, survey session, open record, and stable evidence links as `Resume this report`; it cannot truthfully claim to know the reader's prior task or algorithmic next-best action (C004; explicit inference, unvalidated for static reports).

## Selected direction

**[J] Field Docket, tightened** keeps the earlier prototype's sound core while correcting its most important ambiguity:

> Lead with consequence, keep the coordinate, expose the warrant, and make every continuity claim identify who owns the state.

The generated surface has six global destinations:

`Overview · Action · Atlas · Casefiles · Proof · Reference`

`Resume this report` is an in-page route, not a promise of personal memory. Its basis must be visible:

- `Active survey session` when the generator records one;
- `Open engineering action` when a finding record requires it;
- `Needs human decision` when an open question changes interpretation;
- `No prior publication comparison recorded` when no durable baseline exists.

It never derives “what you were doing” from a timestamp, current URL, or localStorage. Optional device-local pins may exist only if explicitly labeled, inspectable, resettable, and kept separate from generated publication state.

## First-viewport contract

1. Project identity and one-breath system model.
2. Active-run caveat if the visible snapshot predates ongoing work.
3. A consequence-led action queue: critical/high open findings, then decisions changing their interpretation.
4. Four separate conditions: source alignment, survey depth, engineering action, publication integrity.
5. Stable routes: resume this report, understand the terrain, inspect casefiles, prove the projection.

No composite health score, completion ring, ambient animation, or write-looking control is permitted.

## MVP renderer sequence

1. **Make existing language truthful.** Remove the duplicated hint. Replace `No recorded stale entries` with `Source scan: no tracked records flagged for re-check`. Give contradiction zero states an evaluated/not-evaluated basis.
2. **Separate status domains.** Survey depth, finding resolution, severity, source alignment, and proof state get distinct names and accessible descriptions. Green `Mapped` must not read as code health.
3. **Make findings readable.** Render one `<article data-finding-id>` per finding with consequence, observation, cause, business context, primary files, checked SHA, resolution, assumptions, and durable/source routes.
4. **Make the overview actionable.** Query critical/high engineering actions and human decisions from existing records. Display the active-run caveat before counts. Keep actions honest links or copyable commands.
5. **Make state history legible.** Current structured state is authoritative; embedded earlier survey prose is labeled as dated phase history or becomes an explicit conflict record.
6. **Repair the mobile drawer.** Closed means inert/untabbable; open transfers and traps focus; Escape resets state and returns focus.
7. **Add a generated content index later.** Search result types include subsystem, finding, decision, concern, file, and evidence. Offline operation and no-JS reading remain intact.

Architecture visualization and publication-to-publication delta follow only after the MVP has truthful inputs. A graph with nodes but no edges and a delta inferred from timestamps both fail closed.

## Acceptance gates

| Gate | Turns red when | False-green warning |
| --- | --- | --- |
| Finding custody | Any database finding lacks exactly one semantic article, marker, anchor, subsystem link, resolution, consequence, cause, SHA, and evidence route | Presence does not establish evidence correctness. |
| Overview reconciliation | Action, verification, decision, contradiction, or tracked-stale counts differ from durable records; active run lacks a prior caveat | A reconciled editorial ranking can still prioritize badly. |
| Status separation | A badge lacks exactly one domain or an accessible non-`title` explanation | Upstream state may still be wrong. |
| Resume ownership | Personal/history language appears without an explicit disclosed local/user state source | Correct copy does not prove the route improves re-entry. |
| Epistemic zero state | A bare “none recorded” lacks scope, basis, and checked revision | The upstream workflow may falsely mark a check complete. |
| Mobile keyboard | Closed rail remains tabbable; Escape fails to reset/return focus; background remains active | Automation is not assistive-technology validation. |
| Architecture correspondence | A graph fallback is presented as a diagram or a visible edge lacks a readable linked equivalent | Correct correspondence does not prove the map aids comprehension. |
| Current fixture | Prototype counts do not reconcile to `34/34`, `15`, `1 critical`, `2 high`, and the current active-session state | A moving source can invalidate a previously correct fixture. |

## What remains genuinely unresolved

1. Whether project thesis or critical consequence should receive the first visual emphasis; test both orders with representative maintainers and newcomers.
2. Whether report-owned `Resume this report` is discoverable without sounding personalized; Scholiast open question O001 requires prototype testing.
3. Whether action ordering should include reachability and decision dependency in addition to severity; the rule needs explicit data and red tests before it can claim “next.”
4. Whether projection incoherence should block publication or be disclosed; the safer policy likely belongs in readback, not styling.
