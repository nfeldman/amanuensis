# Codex review of the code-index plan

`codex exec -s read-only -m gpt-6.1-sol`, 2026-11-21, against PLAN.md as first drafted (before the dispositions in PLAN §12). 190,343 tokens. Verbatim below, except that absolute home-directory paths are shortened to `store-only:<path>` (the store-only worktree). PLAN line numbers refer to the first draft.

Reviewed the primary checkout at `32ad430` and store-only worktree at `504cdd2`. No tests, builds, installations, or writes were run; the excluded inspiration directory was not opened. Code references below refer to the store-only worktree unless stated otherwise.

1. **High — Official tag queries do not provide the promised definition coverage or body spans.** Location: [§4.2 and SI5](design/semantic-index/PLAN.md:276). The pinned [C query](https://raw.githubusercontent.com/tree-sitter/tree-sitter-c/v0.24.1/queries/tags.scm) captures `function_declarator`, which excludes the function body. A body edit would therefore leave its “body hash” unchanged. The [TypeScript query](https://raw.githubusercontent.com/tree-sitter/tree-sitter-typescript/v0.23.2/queries/tags.scm) also omits type aliases; the inherited JavaScript query omits ordinary variable definitions. Real coordinates would be refused under D4. **Fix:** specify supplemental queries and full declaration spans per language. Golden fixtures must include function-body edits, type aliases, constants, constructors, and other supported definition forms—not merely one convenient definition per language.

2. **High — Qualified names are insufficient to identify symbols in several supported languages.** Location: [§4.2–4.5](design/semantic-index/PLAN.md:280). Enclosing-definition spans cannot qualify Go methods by receiver because their types are declared elsewhere. Rust `impl` targets likewise are not enclosing definitions in the pinned [Rust tags query](https://raw.githubusercontent.com/tree-sitter/tree-sitter-rust/v0.24.0/queries/tags.scm); that query additionally captures methods as both methods and functions. Java overloads share a class-and-name qname. Consequently, `read_symbol` can remain ambiguous even with a qname, while refresh provides no ambiguous state. **Fix:** define receiver/implementation-aware names, deduplicate captures, and add a stable discriminator for overloads. Test duplicate names and collisions through reads, evidence insertion, and refresh.

3. **High — Unchanged source bytes do not justify the proposed refresh clearance.** Location: [§4.5 and §5](design/semantic-index/PLAN.md:368). A function can retain identical bytes while an imported function, module constant, configuration, caller, or surrounding initialization changes its behavior. Moreover, [clear_staleness](store-only:mcp-server/src/tools/stale.ts:113) clears the entire ledger file, whereas `anchor_state` describes individual evidence rows. One unchanged anchor cannot vouch for other evidence, uncited changes, or file-wide claims. **Fix:** make this a textual-change hint. Require review of relevant changes and dependencies before clearance, and explicitly account for all obligations associated with the file. Add a fixture where the function body stays identical but its behavior changes.

4. **High — Overlap permits evidence to cite material outside the symbol whose hash supposedly protects it.** Location: [§4.4](design/semantic-index/PLAN.md:343). A whole-file range overlaps any contained function; its excerpt can come from a different function and still pass the existing citation check. Comma-separated ranges are already supported by [requireEvidenceCitation](store-only:mcp-server/src/helpers.ts:473), but the new overlap rule does not define their treatment. Separately, a truncated 400-line symbol read returns an anchor for source the agent has not fully seen. **Fix:** require every cited span and excerpt to lie within the anchored definition, with an explicit policy for documentation. Distinguish the definition’s full span from the span actually returned/read, and gate both cross-symbol citations and truncated reads.

5. **High — Blob hash alone is not a valid parse-cache key.** Location: [§4.1](design/semantic-index/PLAN.md:254). The same blob can appear as `.ts`, `.js`, `.py`, or another language, including after a rename. Git hashes content independently of the path’s language. `blobs(blob_sha PK, lang, …)` therefore lets the first interpretation determine subsequent results, contradicting the claim that the cache cannot disagree with a revision. **Fix:** key parsed results by blob hash, language, and extractor/grammar identity. Keep path-dependent interpretation in the tree mapping. Add same-content/different-extension and extension-changing rename fixtures.

6. **High — Sidecar rebuild and publication have no multi-process protocol.** Location: [§4.1 and SI6](design/semantic-index/PLAN.md:254). Multiple servers can discover a missing blob simultaneously; one can observe partially populated tables or a tree before indexing finishes. More seriously, old and new server versions sharing storage will repeatedly invalidate the global metadata and rebuild each other’s cache. “Replace a corrupt sidecar” is also unsafe while another process holds it open. **Fix:** specify transactional publication, completion markers, uniqueness/upsert behavior, busy handling, and generation-specific cache ownership. Test concurrent readers/builders, interrupted construction, and two extractor versions running together.

7. **Medium — The git-input failure contract is incomplete and cannot distinguish absence from inability to inspect.** Location: [§4.1, §4.3, §4.5 and SI6](design/semantic-index/PLAN.md:267). Refresh offers `gone`, but no state for missing historical blobs, an unavailable grammar, parse failure, an oversized file, or cache failure. The prototype’s `ls-tree` parsing also lacks NUL-delimited paths and mode handling ([index.mjs:40](design/semantic-index/baseline/index.mjs:40)); quoted filenames, symlinks, and gitlinks need explicit treatment. The file/count caps still permit roughly 40 GB of input and do not bound execution time or retained blob storage. **Fix:** define unavailable/partial outcomes separately from `gone`; specify tree modes, encoding policy, aggregate budgets, cancellation, and cache collection. Cover shallow/missing-object cases, unusual filenames, gitlinks, invalid UTF-8, and CRLF.

8. **High — Records indexing misses legitimate updates, and its cursor assumption does not match the schema.** Location: [§4.6 and SI8](design/semantic-index/PLAN.md:375). Vocabulary is upserted in place, including `gloss` and `expansion` ([vocabulary.ts:129](store-only:mcp-server/src/tools/vocabulary.ts:129)). Re-reading matching hits cannot make newly added vocabulary searchable: the stale FTS index will never select that row for its new words. Also, declared IDs for claims and findings are caller-supplied text, and vocabulary is keyed by `term`, not an increasing `id`. **Fix:** define insertion cursors explicitly, plus a change cursor or content-digest reconciliation for mutable text. Gate an update introducing a previously absent search term and an insertion whose textual key sorts before existing keys.

9. **Medium — Records search can resurrect superseded or withdrawn accounts.** Location: [§4.6](design/semantic-index/PLAN.md:375). Indexing every append-only narrative/explanation row and reporting its row-level status bypasses store-only’s effective-record semantics. The existing readers deliberately distinguish current, withdrawn, historical, unreachable, and phase-ineligible records ([get_narratives](store-only:mcp-server/src/tools/narratives.ts:300), [get_explanations](store-only:mcp-server/src/tools/explanations.ts:354)). An old row still says `disposition='recorded'` after replacement or withdrawal. **Fix:** resolve search hits through those effective-record rules, default to effective records, and expose history only explicitly. Gate replacement, reset/withdrawal, and unreachable revisions.

10. **Medium — The sidecar exclusion misses storage migration.** Location: [§4.1 and SI6 deliverables](design/semantic-index/PLAN.md:241). [storageManifest](store-only:mcp-server/src/project.ts:313) excludes only `CALL_LOG_DIRECTORY`. Its content hashes are used for migration verification and conflict detection. Two otherwise identical stores with different code caches will conflict; concurrent indexing can also make a correct cross-filesystem migration fail read-back. `project.ts` is absent from SI6. **Fix:** exclude `code-index/` from record manifests and define its treatment during copying/reconciliation. Extend the existing migration fixtures with differing and actively changing caches.

11. **Medium — The anchor API and existing evidence readers have not been reconciled.** Location: [§4.3–4.4, SI7 and SI9](design/semantic-index/PLAN.md:302). The returned anchor uses `path` and `qname`, while [add_evidence](store-only:mcp-server/src/tools/evidence.ts:30) requires `file_path`, `ref_sha`, and `kind`, rejects additional properties, and accepts neither blob nor body hashes. No replacement input contract is specified. Existing symbol readers also use exact `e.symbol` equality ([locus.ts:425](store-only:mcp-server/src/tools/locus.ts:425)), so accepting both bare and qualified aliases creates inconsistent retrieval. SI7’s acceptance gate precedes SI9’s ingress changes. **Fix:** define the precise anchor input, authoritative revalidation, canonical identity and legacy matching rules; update affected readers; insert evidence and anchor atomically; and correct the dependency/gate boundary.

12. **Medium — The transcript baseline measures tool categories, not source-code reading.** Location: [§2.1](design/semantic-index/PLAN.md:111). [transcripts.py:22–34](design/semantic-index/baseline/transcripts.py:22) assigns every command containing `amanuensis` to tooling before checking whether it reads source. Conversely, `Read`, `cat`, and `sed` count as source reads regardless of the target. Classifying a multi-command invocation by its last command attributes all preceding output to that category. The arithmetic produces 75.4% and 66.5%, but neither percentage establishes the asserted source-code share. **Fix:** retain target-aware classifications, mark mixed shell output separately, and report unknown attribution. Keep context-weighted bytes explicitly as an approximation rather than treating them as measured cache-read token occupancy.

13. **Medium — The evidence census does not implement the ingress check or the proposed resolver.** Location: [§2.2 and SI11](design/semantic-index/PLAN.md:152). [evcheck.mjs:28–35](design/semantic-index/baseline/evcheck.mjs:28) decodes HTML entities, drops short elision fragments, and normalizes whitespace differently from the real checker, which rejects HTML-escaped quotations. Its resolver strips qualification and accepts an arbitrary matching definition ([lines 62–67](design/semantic-index/baseline/evcheck.mjs:62)), unlike the planned unique-name resolution. Finally, “recoverable” means found anywhere in the file, not recoverable inside the cited symbol. **Fix:** share the actual citation/resolution semantics and distinguish parser omissions, ambiguity, genuinely absent symbols, and relocation into the correct definition. Do not describe all eight anywhere-in-file recoveries as repairs anchoring will deliver.

14. **Medium — The reported size reductions compare inconsistent quantities.** Location: [§2.2–2.3](design/semantic-index/PLAN.md:169). `evcheck.mjs:68` counts symbol size as `endIndex-startIndex` but file size with `Buffer.byteLength`. The web binding exposes UTF-16 code-unit offsets through its [conversion layer](https://raw.githubusercontent.com/tree-sitter/tree-sitter/v0.27.2/lib/binding_web/lib/tree-sitter.c), so those quantities differ for non-ASCII source. [retrieval.mjs:52](design/semantic-index/baseline/retrieval.mjs:52) excludes indexed names and paths from symbol size while counting untruncated documentation that the index truncates. Thus the 28-fold figure is not a comparison of actual indexed text sizes. **Fix:** count serialized inserted fields consistently in UTF-8, measure database size separately, and specify conversion from parser offsets to the proposed byte coordinates. Add Unicode fixtures.

15. **High — The retrieval experiment is unsuitable as the current embedding decision gate.** Location: [§2.3, §6.6 rule 3 and SI11](design/semantic-index/PLAN.md:180). Queries include disposition evidence text, which can contain the answer’s file/symbol vocabulary ([retrieval.mjs:58–61](design/semantic-index/baseline/retrieval.mjs:58)); targets come from historical evidence while the index uses one different revision. Unsupported files receive only a path entry in the symbol arm but their full bodies in the file arm. The top-200-symbol cutoff can prevent reaching ten distinct files, and hitting any one cited file is hit rate, not coverage of all cited files. These effects can either manufacture or conceal the condition opening embeddings. **Fix:** use independently frozen queries with verified targets present at the indexed revision, separate navigational and semantic queries, restrict or stratify eligible languages, and compute genuine top-k distinct-file results using a declared hit/recall metric.

16. **High — A0 retains instructions to call tools it does not have.** Location: [§5 and §6.4](design/semantic-index/PLAN.md:495). A0 removes `code-index.md` and the reading-order section, but §5 also rewrites the phase-1 through phase-4 references, refresh, and notes to require index tools. Those instructions survive in A0. Baseline retries and confusion can therefore appear as index savings. In addition, T1’s write validation differs between arms despite the claim that it isolates reading. **Fix:** freeze a complete baseline skill tree, verify every callable reference against each arm’s advertised tools, and define whether the estimand is the entire new workflow or reading alone. A reading-only claim needs equivalent citation validation.

17. **High — The executable benchmark lacks its scoring implementation and an anchored T3 fixture contract.** Location: [§6.3, SI1–SI3 and SI14](design/semantic-index/PLAN.md:476). Tasks promise mechanical scoring and post-run key decryption, but no packet delivers or gates a scorer. SI14 consumes already scored results. T3 additionally needs evidence anchored at its old revision; SI1 freezes stores before anchors exist, D6 forbids automatic backfill, and no later packet specifies a deterministic benchmark-only preparation step. **Fix:** add scorer and fixture-builder deliverables, with independently keyed positive/negative cases. Require T3 to contain verified anchored evidence covering every state, then freeze the final fixtures and hashes before estimation runs.

18. **High — Excluding A1 non-use selects the treatment results after observing behavior.** Location: [§6.4 and SI14](design/semantic-index/PLAN.md:514). Tool availability plus guidance is the treatment being proposed for default adoption. An agent choosing not to use it is a legitimate outcome. Declaring those runs VOID can remove expensive or unsuccessful A1 sessions and certify a saving among selected users. Excluding VOIDs also has no explicit minimum retained sample count or missing-cell refusal rule. **Fix:** retain assigned runs in the primary analysis, report tool use as a manipulation/compliance measure, and keep any per-protocol analysis secondary. Pre-register valid-sample minimums and rules for failures, attrition, and retries.

19. **High — MDE is being used as an evidence threshold instead of a power property.** Location: [§6.5–6.6](design/semantic-index/PLAN.md:522). An observed median reduction exceeding `max(10%, MDE)` does not establish that the saving exceeds noise. The decision has no uncertainty requirement, while variance is estimated from only two pilot runs per cell. Pooling raw token totals across heterogeneous tasks also leaves the weighting and estimand unclear. **Fix:** pre-register the estimand, task/subject weights, randomized blocked order, uncertainty method, and false-positive/power targets. Require an interval or corresponding predeclared test to support the adoption threshold; use pilot-derived MDE to choose sample size, not to certify the observed result.

20. **High — The quality rule explicitly permits measurable harm and even vacuous success.** Location: [§6.6, D9 and SI14](design/semantic-index/PLAN.md:532). One allowed step is one wrong answer per run: 10% on T1, 12.5% on T2, and 20% on T4. That is observable degradation, not a difference below resolution. There is also no absolute quality floor: equally unsuccessful arms can satisfy the quality condition while the cheaper failure wins. This contradicts §6.3’s assurance that savings were not bought with quality. **Fix:** add absolute competence floors and a justified noninferiority requirement. If the owner wants a quality-for-cost tradeoff, name and authorize it explicitly instead of recommending it as evidence of preserved quality.

21. **High — SI4 contains an impossible acceptance condition and an incomplete installation change.** Location: [SI4](design/semantic-index/PLAN.md:611), [plan.json:284](design/semantic-index/plan.json:284). “No runtime dependency has an install script” rejects the existing `better-sqlite3` runtime dependency: [package-lock.json:334–338](store-only:mcp-server/package-lock.json:334) declares `hasInstallScript: true`. Applying `--ignore-scripts` to the entire installation also suppresses its native setup. Existing CI uses ordinary `npm ci`, and no workflow change is assigned. **Fix:** scope the prohibition to newly introduced index dependencies. Specify a selective grammar-fetch/vendor procedure, or an explicit native-dependency rebuild, and assign the corresponding CI edits. Preserve working Node 20/22 installation.

22. **Medium — The lane can finish without validating the installed feature or applying its measured decision.** Location: [SI12–SI14 and completion commands](design/semantic-index/PLAN.md:660). No packet adds the new gates to CI or makes an installed tarball exercise grammar loading and the four tools. Existing Node-floor CI runs protocol compatibility only ([test.yml:619](store-only:.github/workflows/test.yml:619)); package checks can therefore pass while runtime assets are missing. Separately, SI12 installs mandatory guidance before R3, but no post-R3 step applies the optional/default outcome promised by §6.6. **Fix:** assign installed-artifact feature checks across Node 20/22 and macOS/Linux, register the new regression gates in CI, and add an outcome-application step that gates the final skill against the retained decision artifact.

Overall, I would request changes before launching the lane. The sidecar/cache separation and additive anchor table are reasonable foundations, but the current plan can produce incorrect symbol hashes, overstate refresh safety, miss record updates, and certify token savings caused by selection or quality loss. The headline arithmetic is largely consistent with the retained aggregates; the stronger interpretations and adoption rules are not yet supported. Resolve the extraction, identity, refresh, concurrency, and benchmark contracts first, then revise packet dependencies and acceptance evidence around those decisions.
