# Dated project and approach matrix

**Snapshot date: 2026-08-22.** This is a project/capability matrix, not a popularity ranking. Source IDs resolve through [`sources.md`](sources.md). Health numbers come from the bounded snapshots in S028 and S060; package sizes and dependency counts have the scope caveats in S029, S037, S042, and S060.

Legend:

- **Direct**: copied output is expected to work from `file://` without a prior online visit.
- **Local HTTP**: remote-asset-free output works behind a tiny static server; direct-file interactive behavior is not promised.
- **Hosted/static**: ordinary static hosting is the primary contract.
- Build footprint is installed/package cost, never browser payload.
- “Substantial” and “thin” use the operational definitions in [`taxonomy.md`](taxonomy.md).

## Matrix integrity notes

- No unexecuted candidate is described as “fast,” “accessible,” or “secure.”
- Null health response samples mean unavailable under the bounded query, not zero response time.
- Trial outputs are surface-comparable feasibility fixtures, not representative project benchmarks; timing is a sanity check only (S035, S039).
- The combined npm audit is not a clean bill of health for other rows. Its one advisory is scoped to a Windows development server and does not affect the generated report runtime (S038).
- The registry-trial audit independently found the same advisory range through its Vite/esbuild graph; its generated report likewise has no esbuild runtime (S064).
- Copy-owned rows separate local file ownership from imported package ownership. A row is not labeled dependency-free merely because it has no component npm package.
- Direct-file behavior is preferred, not mandatory. Requiring local HTTP is charged explicitly but is not an automatic rejection.
