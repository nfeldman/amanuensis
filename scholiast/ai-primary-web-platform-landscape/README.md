# AI-primary web-platform landscape

**Decision snapshot: 2026-08-22.** Direct `file://` use is preferred, not mandatory.

## Result

Keep Amanuensis’s Python model → deterministic projection → independent read-back architecture. Evolve its output as a platform-first, progressively enhanced multi-page report: complete semantic HTML before JavaScript, shared content-hashed local assets for the folder profile, a no-JS-reachable narrow-screen index, and bounded enhancement at stable DOM boundaries.

The candidate landscape is substantial but specialized:

- copy-owned registries are a real source-distribution category, not a rendering architecture: shadcn has the deepest general protocol, Park is the strongest cross-framework peer, Intent is the React Aria variant, ReUI/Kibo serve complex dashboards, and HyperUI/Chakra/Catalyst are meaningful gallery, hybrid, and commercial variants;
- native Custom Elements are the first extension boundary; Lit is conditional when native lifecycle code becomes repetitive;
- Quarto is the best optional analytical/single-file export candidate, pending an executed representative trial;
- Eleventy is the best external static-generator fallback; Astro is conditional on a real component/island requirement;
- Observable Framework is a credible analytical annex, not the primary shell today;
- Plot/Vega-Lite, then Perspective or DuckDB-Wasm, belong behind a measured visualization/exploration threshold;
- React, Preact, Svelte, Qwik, htmx, VanJS, Alpine-as-shell, client-only primary content, and CDN/`latest` resolution are explicitly rejected for the current primary surface.

No credible evidence found here establishes a universal framework ranking for AI authors. The practical AI-primary advantage comes from validation leverage: small explicit vocabularies, source-to-DOM locality, deterministic artifacts, independent read-back, red-proofed output gates, and explicit browser/accessibility gates still to execute.

The copy-owned extension does not change the primary recommendation. Its pinned `shadcn@4.19.0` trial showed why: the same copied source produced either a complete 46,216-byte static document or a 278,244-byte client-owned artifact with no primary static structure. The registry improved acquisition/diff visibility; pre-rendering, semantics, offline packaging, and validation still came from the surrounding architecture. The full isolated CLI/build tree measured 397 package directories / 189.7 MB, and the copied/init layer retained React, Base UI, class-variant, and class-merge package abstractions.
