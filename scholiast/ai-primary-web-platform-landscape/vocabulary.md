# Vocabulary

| Term | Uses encountered | Working distinction for this survey |
|---|---|---|
| AI-primary | Could mean AI writes most bytes, makes most architectural choices, or merely performs routine edits. | AI is the principal code author and a frequent code reader; human operators remain the source of goals and final authority. Evaluate code legibility to both. |
| Web platform | Sometimes means any browser-delivered app; sometimes only standards-native HTML/CSS/JS without framework abstractions. | Browser primitives and standards are the substrate. Libraries may qualify when they preserve inspectable DOM semantics, progressive enhancement, and low operational coupling. |
| Vanilla | Can mean “no framework,” “no build,” or “only browser APIs.” | Use only with a qualifier: no runtime dependency, no build dependency, or standards-native authoring. |
| Self-contained | Ambiguous between one HTML file, one offline folder, one archive, and “no server.” | Record four axes separately: single-file, offline-folder, remote-asset-free, and server-free. S003 is offline-folder + remote-asset-free + server-free, not single-file. |
| Static | Can mean pre-rendered HTML, no server, no JavaScript, or immutable content. | Use “pre-rendered,” “server-free,” “script-free,” and “immutable” separately. |
| Lightweight | Commonly hides different costs: install size, runtime bytes, dependency count, build latency, or conceptual surface. | Never use without a measured dimension and unit. |
| Component | May mean a web component/custom element, a framework component, or any modular UI function. | Preserve the qualifying technology in every claim. |
| Accessibility support | Vendor pages often mean primitives exist; conformance means the authored result satisfies WCAG. | Separate structural affordances, executed behavior tests, and conformance audit. A component library cannot confer accessibility automatically. |
| Offline | Can mean service-worker cached after a first visit, a copied folder served locally, or directly openable from disk. | Offline availability is required; direct `file://` is preferred, not mandatory (clarified 2026-08-22). Record direct-file and tiny-static-server profiles separately, plus whether a prior online visit is required. |
| Project health | Often proxied by stars or latest release. | Trailing-year commit cadence, release recency, active maintainer count, and issue/PR responsiveness, with raw dated values. |
| Copy-owned component | Often advertised as “not a component library,” “open code,” or “copy and paste,” even when the copied file imports packaged behavior and utilities. | Component implementation source is materialized into and editable within the consumer repository. Record every remaining package-owned dependency separately; copy ownership is not dependency ownership. |
| Registry | Can mean a searchable gallery, a package registry, a CLI-readable item manifest, or a protocol for distributing arbitrary files and dependencies. | Use “gallery,” “package registry,” or “source registry.” A source registry has machine-readable item metadata and materializes files into a consumer tree. |
| Headless primitive | Sometimes means unstyled, minimally styled, or merely themeable. | A package-owned behavior/semantics layer without a complete visual system. Its accessibility contract remains distinct from the copied wrapper’s markup and styling. |
| Design-system stack | Commonly compressed to a product name even when the delivered component spans framework, primitives, CSS compiler, tokens, class-merging helpers, variants, icons, and copied source. | Enumerate the layers and ownership boundary. The stack is the unit of build/runtime/security cost; the copied file alone is not. |
| Upgrade drift | Can refer to intentional local customization, registry version lag, dependency incompatibility, or an inability to reapply upstream changes. | The divergence between a materialized local component and the current upstream item after both local and upstream edits. Measure three-way merge/review cost rather than treating divergence as automatically good or bad. |
| Block | Used for both a reusable component and a page-scale composition. | A registry item that materializes several components/files and may encode page/application structure. Record file, line, dependency, and context volume separately from atomic components. |
